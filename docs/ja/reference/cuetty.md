# コマンドラインでのレンダリング (cuetty)

`cuetty` は、GUI を使わずにシーンファイル (`.qsc`) から画像を書き出すコマンドです。
レンダリングウィンドウと同じ [Umbreon](rendering.md) で描画し、ウィンドウも GPU も
使わないので、ディスプレイの無いサーバーやクラスタの計算ノードでも動きます。
シーンのアニメーションを、動画のフレーム (連番の PNG) として書き出すこともできます。

```sh
cuetty --input scene.qsc --render out.png --width 1920 --height 1080
```

## 入手

cuetty は Linux (x86-64) 用の `cuetty-<version>-linux-x64.tar.gz` として配布しています。
macOS / Windows の CueMol3 には含まれていません。起動中の CueMol3 に画像を書き出させる場合は
[tritium_cli](plugins/console/cli.md) を使います。
[GitHub の Releases](https://github.com/CueMol/cuemol3/releases) から入手します。
展開した場所で、パスを指定して実行します。root 権限や `LD_LIBRARY_PATH` の設定は要りません。

```sh
tar xf cuetty-<version>-linux-x64.tar.gz
cuetty-<version>-linux-x64/bin/cuetty --input scene.qsc --render out.png
```

動作には次のものが必要です。

- glibc 2.28 以降の x86-64 の Linux (RHEL / Rocky / Alma 8・9、Ubuntu 20.04 以降、Debian 10 以降)。
- **x86-64-v3** (AVX2 / FMA / BMI1・2) に対応した CPU (Intel Haswell / AMD Zen 以降)。
  古い CPU では、起動時に終了ステータス 1 で終了します。
- GPU とディスプレイは不要です。ノイズ除去 (OIDN) も CPU で行います。
- メモリは、既定の設定で 1200×1200 px の画像を描いたときに最大約 3 GB でした。
  画素数とスーパーサンプリングの倍率に比例して増えます。ジョブのメモリの割り当ての目安にしてください。

## 静止画

`--render` に出力先の PNG を指定すると、画像を書き出して終了します。

| オプション | 既定値 | 説明 |
|---|---|---|
| `--input <パス>` | — | 入力のシーンファイル (`.qsc`)。`--render` / `--movie` では必須です。 |
| `-r`, `--render <パス>` | — | 出力する PNG のパス |
| `--width <px>` / `--height <px>` | シーンの設定 | 画像の幅・高さ。シーンに保存された大きさを上書きします。 |
| `--camera <名前>` | `__current` | 描画に使うカメラ。シーンに保存されたカメラの名前を指定します。 |
| `--threads <数>` | 下記 | 描画に使うスレッドの数 |
| `-h`, `--help` | — | オプションの一覧を表示します。 |

カメラの既定の `__current` は、GUI がシーンの保存時に書き込む、その時点のビューです
(→ [カメラ](camera.md#__current))。

`--threads` を指定しない場合は、環境変数 `SLURM_CPUS_PER_TASK` (Slurm のジョブに割り当てられた CPU の数)、
`OMP_NUM_THREADS` の順に従い、どちらも無ければマシンのすべてのコアを使います。
共用のノードでは、このどれかでジョブの割り当てに合わせてください。

### 設定はシーンから

描画の設定は、シーンに保存されたレンダリングウィンドウの設定 (→ [設定の保存](rendering.md#設定の保存))
をそのまま使います。GUI のレンダリングウィンドウで描いたときと同じ画像になります。
バックエンドに Umbreon (NPR) を選んであるシーンはハッチングで描き、それ以外は Umbreon で描きます。

設定が保存されていないシーンは既定値 (Lighting が Global Illumination、1200×1200 px) で描画され、
投影方式はカメラのものに従います。コマンドラインから変えることができるのは、画像の大きさとカメラだけです。

## 動画のフレーム

`--movie` に出力先のフォルダと名前を `<フォルダ>/<名前>` の形で指定すると、シーンのアニメーション
([Animation パネル](../ui/bottom-panels/animation.md)で編集するもの) を、
`<名前>_frm_0000.png`、`<名前>_frm_0001.png`、… の連番の PNG として書き出します。
ファイル名は GUI で動画を書き出したときと同じです。

```sh
mkdir -p frames
cuetty --input scene.qsc --movie frames/movie --fps 30
```

| オプション | 既定値 | 説明 |
|---|---|---|
| `--movie <フォルダ>/<名前>` | — | 出力先のフォルダと名前。**フォルダはあらかじめ作っておきます** (cuetty は作りません)。 |
| `--fps <数>` | 30 | フレームレート。フレーム数は、アニメーションの長さ × フレームレート + 1 です。 |
| `--no-last-frame` | OFF | 最後のフレームを書き出しません。最初と最後が同じになるループの動画に使います。 |
| `--frames A-B` | すべて | フレーム A〜B (両端を含む、0 始まり) だけを書き出します。 |
| `--shard I/N` | — | フレームを連続した N 個に分け、I 番目 (0 始まり) を書き出します。`--frames` とは一緒に使えません。 |
| `--skip-existing` | OFF | ファイルがすでにあるフレームを飛ばします。中断したジョブを再開するときに使います。 |
| `--list-frames` | — | フレーム数を表示して終了します。`--shard 0/N` を付けると、N 個に分けたときの各部分の範囲も表示します。 |

- 各フレームは静止画と同じく、シーンの描画の設定と `--width` / `--height` で描きます。
  開始時のカメラはアニメーションで指定したカメラで、指定が無ければ `--camera` のカメラです (GUI と同じ)。
- 途中のフレームから描く場合も、それより前のフレームを描かずにアニメーションを進めるので、
  全フレームを 1 回で描いたときと同じ画像になります。
- フレームは書き終えてからファイル名を付けるので、存在するフレームのファイルは必ず完全な画像です。
  `--skip-existing` で書きかけのファイルが残ることはありません。フォルダにあるフレームは消しません。

cuetty が書き出すのはフレームだけです。動画にまとめるには ffmpeg などを使います。
GUI で MP4 (H.264) を標準の画質で書き出すときと同じ設定は次のとおりです (`-r` と `fps=` は `--fps` に合わせます)。

```sh
ffmpeg -r 30 -i frames/movie_frm_%04d.png -an -crf 23 -c:v libx264 -f mp4 \
    -vf "fps=30,format=yuv420p" -y movie.mp4
```

### PC クラスタを使った分散レンダリング

フレームを複数のジョブに分けて、別々のノードで並行して描くことができます。
Slurm の array job の例です。

```sh
#!/bin/bash
#SBATCH --array=0-3
#SBATCH --cpus-per-task=16
CUETTY=$HOME/cuetty-<version>-linux-x64/bin/cuetty
$CUETTY --input scene.qsc --movie frames/movie --fps 30 \
    --shard $SLURM_ARRAY_TASK_ID/$SLURM_ARRAY_TASK_COUNT
```

- **出力先のフォルダは、投入する前に作っておきます** (`mkdir -p frames; sbatch movie.sh`)。
  NFS では、あるノードで作ったフォルダが別のノードからすぐに見えないことがあるため、
  cuetty はフォルダを作りません。
- array の番号は 0 から隙間なく振ります (`--array=0-3`)。`--array=1-4` にすると 1/4〜4/4 になり、
  0 番目の部分が抜けます。
- 各ジョブは割り当てられた CPU の数 (`SLURM_CPUS_PER_TASK`) で描きます。
- 途中で止まったジョブは、`--skip-existing` を付けて投入し直すと、足りないフレームだけを描きます。

## シーンのデータを持ち込む

シーンファイルは、データを埋め込んで保存していなければ、分子などのデータを元のファイルから読み込みます。
別のマシンで描くときは、次のどちらかにします。

- データを埋め込んでシーンを保存する (→ [シーンの保存](save-scene.md))。
- シーンが参照しているファイルを、同じパスで見えるようにコピーする。相対パスは `.qsc` のあるフォルダから解決します。

MD トラジェクトリは、データを埋め込んで保存したシーンでも常に別のファイルのままです。
`.qsc` との位置関係を保ってコピーしてください。

**データを読み込みきれないシーン** (参照先のファイルが無い、埋め込んだデータが壊れている・欠けているなど) は、
欠けたまま描かずにエラーで終了します。

## 終了ステータス

| ステータス | 意味 |
|---|---|
| 0 | 書き出しました。 |
| 1 | シーンを読み込みきれない、指定したカメラが無い、引数が正しくない、画像を書き出せない、CPU が古い、のいずれかです。 |

失敗した理由はログに出力されるので、スクリプトではステータスだけで分岐できます。

```sh
if ! cuetty --input scene.qsc --render out.png --width 1200 --height 900; then
    echo "render failed" >&2
    exit 1
fi
```

!!! warning "原子ラベルなどの文字は描画されません"
    原子名や距離の測定値などのラベルは画像に入りません (エラーにはならず、ラベル以外は描かれます)。
    ラベルの入った図が必要な場合はレンダリングウィンドウをお使いください。

## Python から描く

`cuemol` の Python モジュールからも、同じ経路 (Umbreon) で描画できます。
描画の設定はシーンに保存されたものを使い、cuetty と同じ画像になります。

```sh
python -m cuemol.umbreon_render scene.qsc out.png -W 1920 -H 1080
```

`-c` でシーンに保存されたカメラを指定できます。省略した場合は `__current` を使います。
`-W` / `-H` は保存されたサイズを上書きします。
