    Console¶

    CueMol の操作をコマンドで実行するコマンドラインです。既定で有効のプラグインで、 下部パネルの Console タブから使います。ターミナルから同じコマンドを実行する tritium_cli も同梱されています (→ tritium_cli)。

    コマンドのモードは 2 つあり、パネルで切り替えます。

    モード プロンプト 内容
    native モード (既定) CueMol> CueMol 自身の操作のコマンド。選択は CueMol の選択式で書きます。このページで説明します
    PyMOL 互換モード PyM> PyMOL 互換のコマンド (→ PyMOL 互換モード)

    撮影予定

    有効にする¶

    既定で有効なので、下部パネルの先頭に Console タブがあります。ほかのタブを選ぶまでは、 このタブが前面に表示されます。 使わない場合は Settings > Plugins > Installed で Console を無効にします (→ プラグイン)。

    PyM Console から名前が変わりました

    2.3.20.539 までの PyM Console プラグインは、2.3.21.544 で Console に 変わりました。PyM Console を無効にしていた場合も Console は有効になっているので、 使わない場合はもう一度無効にしてください。PyMOL 互換モードの入力の履歴は引き継がれます。

    モードの切り替え¶

    • ツールバー左端の CueMol | PyMOL で切り替えます。CueMol が native モードです。
    • 行に native または pymol とだけ打って実行しても切り替わります。
    • 選んだモードは記憶され、次に起動したときもそのモードで始まります。
    • 入力の履歴はモードごとに別々です。

    入力と補完¶

    操作 動作
    Enter コマンドを実行します
    Shift+Enter 改行します
    Tab カーソルより前の部分を補完します。カーソルより後ろはそのまま残ります。候補が複数あるときは、プロンプトのすぐ上に一覧が表示されます。一覧が出ているときにもう一度押すと、候補を選ぶメニューになります
    Up / Down 入力の履歴をたどります (カーソルが先頭行 / 最終行にあるとき)
    • 候補のメニューでは、Tab / Shift+Tab / 矢印キーで候補を移り、Enter で確定します (コマンドは実行されません)。Esc を押すと、Tab を押す前の入力に戻ります。 そのほかのキーを打つと、選んでいる候補を確定してからそのキーが入力されます。 候補はクリックでも確定できます。
    • * や ? を含む語で Tab を押すと、一致するものすべてに展開されます。
    • ファイル名の補完では、. で始まる名前は . を打ったときだけ候補になります。一致する ものが無ければ、大文字と小文字を区別せずに探し直します。cd ではディレクトリだけが候補になります。
    • native モードの Tab は、コマンド名、help の項目、引数の値 (選択肢や true / false)、 Object・Renderer の名前、名前付き選択、色の名前、Renderer の種類、プロパティのパス、 まだ指定していない引数の name=、ファイルのパス (パスを取る引数のみ) を補完します。
    • 1 回の実行が 1 回の Undo にまとまります。
    • ツールバーの Clear で記録領域を消去し、Help でいまのモードの help を実行します。
    • 実行中は「Running...」の横に Stop が表示されます。押すと次のコマンドの前で止まります。 それまでに実行した分は残ります。

    native モードの書き方¶

    zoom 1crn, chain A and resid 10:20
set 1crn/cartoon1.width, 2
create_renderer 1crn, ballstick, name=bs1
    • コマンド名のあとに引数をカンマで区切って並べます。name=value の形で引数の名前を 指定することもできます。
    • コマンド名は「動詞_対象」の形です (list_cameras / add_paint など)。props / view / slab のように名詞だけのコマンドは、値を付けずに打つとその内容を表示し、値を付けると設定します。
    • Object は名前 (1crn)、Renderer は Object名/Renderer名 (1crn/cartoon1) で指定します。 Renderer 名だけでも、シーン内で一意なら通ります。どの要素も #12 のように uid で 指定できます。名前が曖昧なときは実行されず、候補の uid が表示されます。
    • プロパティは要素のあとに . で続けます (1crn/cartoon1.width、view.centerMark)。 シーンのプロパティは名前だけで指定します。
    • help は項目の一覧を、help <項目> はその項目のコマンドの一覧を、help <コマンド> または <コマンド> ? はそのコマンドの書式と引数の表を表示します。help syntax は コマンドの書き方の説明です。

    複数の対象とワイルドカード¶

    Object・Renderer・プロパティのパスと、読み込むファイルのパスは、空白で区切って複数 並べられます。* と ? のワイルドカードも使えます。

    hide 1crn 2abc/cartoon1
set */simple1.width, 0.7
load *.pdb ~/pdb/1c*.pdb
get_prop *.visible
    • コマンドは対象ごとに 1 回ずつ実行されます。失敗した対象は警告になり、残りの対象は 実行されます。何にも一致しないパターンは no matches found: <パターン> の警告になります。
    • 複数並べた場合も、行全体が 1 回の Undo にまとまります。
    • 空白を含む名前は、引用符で囲むか ("my mol")、空白の前に \ を付けます (my\ mol)。 * そのものは \* と書きます。
    • props (list_node_props) と get (get_prop) は結果を表で表示します。対象が複数のときは 1 つの表にまとめます。

    空白を含む名前には引用符が必要です

    2.3.21.544 までは、空白を含む Object 名や Renderer 名、パスを引用符なしで書けました。 2.4.0.546 からは、空白が区切りとして読まれます。

    対応コマンド¶

    native モードのコマンドは、help の項目ごとに Console のコマンド一覧に まとめてあります。

    スクリプトとログ¶

    • run file または @file で、コマンドを 1 行ずつ書いたテキストのファイルを実行します。 スクリプト全体が 1 回の Undo にまとまります。
    • run file.qax (または @file.qax) は、記録された操作のファイル (qax) を再生します。 行にそれだけを書いた場合は、記録された操作ごとに 1 回の Undo になり、失敗した操作の ところで止まります。スクリプトの中から実行した場合は、スクリプト全体の Undo に含まれます (→ 操作の記録と再生)。
    • open_log でファイル (既定は log.qax) を開くと、それ以降の実行で行われた操作が qax として記録されます。シーンを変えなかった実行は記録されません。log で書いた文は メモとして入ります。close_log で記録を終えます。
    • list_actions は Undo の各ステップと、その中で行われた操作を古い順に表示します。 export_actions file[, first[, last]] はその範囲を qax に書き出します。
    • .pml (PyMOL のスクリプト) は native モードでは実行できません。PyMOL 互換モードに切り替えて 実行してください。

    ターミナルから使う (tritium_cli)¶

    tritium_cli は、Console のコマンドをターミナルから実行するクライアントです。 CueMol3 に同梱されています。使い方・接続・PATH の通し方は tritium_cli を 参照してください。

    制限事項¶

    • シーンのコマンド (create_scene / switch_scene / close_scene) と quit / exit は、スクリプトの中では使えません。
    • Python は受け付けません。.py / .pym のスクリプトや、/ で始まる行は拒否されます。
    • AI Agent の指示や MCP Server の呼び出しを実行している間は、コマンドを 実行できません。
